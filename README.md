## 🧬 About Me

<p align="left">
I'm a <strong>Full Stack Developer</strong> with a couple of years of hands-on experience building web apps across small SaaS products, internal tools, and side projects that actually see real users. I care about writing code that's easy to read six months later — clean components, sane API design, and tests that catch the bug before a user does.

Lately I've been going deep on <strong>Web3 and blockchain development</strong> — learning Solidity, poking at smart contracts, and figuring out how dApps actually talk to chains under the hood. I'm also playing with <strong>LLMs and AI tooling</strong>, mostly building small assistants and automations that save me (and hopefully others) time.

I'm not chasing buzzwords — I'm chasing projects where I learn something new every week and ship something I'm proud to link people to.
</p>

## 🚀 Featured Projects

<details>
<summary><strong>⚡ ChainVault — Learning-Focused DeFi Vault Prototype</strong></summary>

<br/>

A personal project built to actually understand how yield vaults work under the hood — a simplified, non-custodial vault contract deployed on a testnet, paired with a clean frontend to deposit, track yield, and withdraw.

<div align="center">

| Attribute | Details |
|:---|:---|
| **Stack** | Solidity, Hardhat, Next.js, wagmi, ethers.js, Tailwind CSS |
| **Focus** | Understanding vault mechanics, gas optimization, and secure withdrawal patterns |
| **Security** | Reentrancy guards, checks-effects-interactions pattern, unit-tested with Hardhat |
| **Status** | Deployed on Sepolia testnet — actively iterating |
| **Repository** | [github.com/rishii-sarkar/chainvault](https://github.com/rishii-sarkar/chainvault) |

</div>

Built this to move past tutorials — designed the contract, wrote the tests, broke it, fixed it, and connected a real frontend so I could see deposits and yield update live on-chain.

</details>

---

<details>
<summary><strong>🧠 DocQuery — RAG-Powered Document Q&A Tool</strong></summary>

<br/>

A small SaaS-style tool that lets you upload documents and ask questions about them in plain English, using retrieval-augmented generation instead of stuffing everything into a prompt.

<div align="center">

| Attribute | Details |
|:---|:---|
| **Stack** | Next.js, FastAPI, LangChain, PostgreSQL + pgvector, Docker |
| **Focus** | Chunking strategy, embedding search accuracy, streaming responses |
| **Performance** | Sub-second retrieval on a few thousand indexed document chunks |
| **Repository** | [github.com/rishii-sarkar/docquery](https://github.com/rishii-sarkar/docquery) |

</div>

Started as a weekend project to learn RAG properly — ended up building a working multi-document Q&A tool with source citations and streaming answers.

</details>

---

<details>
<summary><strong>🛒 ShopFlow — Mini E-Commerce Backend</strong></summary>

<br/>

A headless e-commerce backend built to practice designing clean REST APIs, handling concurrent orders safely, and not overselling inventory during flash-sale-style traffic spikes.

<div align="center">

| Attribute | Details |
|:---|:---|
| **Stack** | Node.js, Express, PostgreSQL, Redis, Docker |
| **Focus** | Inventory locking, order idempotency, Stripe test-mode integration |
| **Testing** | Load-tested locally with k6 to simulate concurrent checkout traffic |
| **Repository** | [github.com/rishii-sarkar/shopflow](https://github.com/rishii-sarkar/shopflow) |

</div>

Focused on getting the boring-but-critical stuff right: no double charges, no overselling, clear error states.

</details>
